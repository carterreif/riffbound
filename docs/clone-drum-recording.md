# Version 98 — Authored Clone Hero Drums for uploaded recordings

Both uploaded recordings and title-only song searches prefer a supported actual Drum track. Clone Hero community Drums use Red, Yellow, Blue and Green pads plus kick; Guitar Hero game conversions retain their five-pad layout. Each instrument must have its own parsed notes. Lookup still checks exact title/artist, recording length, packaged identity, setlist provenance and supported MIDI/.chart features.

Some Clone Hero packages have notes.chart or notes.mid and a single song.opus full recording, without separate instrument stems. Previously uploads required a named Drum stem even after the actual authored Drum chart had parsed successfully. Those packages could therefore fall back to estimation despite containing the desired chart.

The uploaded-recording verifier now opts into full-recording proof for an already-parsed Drum track. This fallback requires exactly one music audio file named song with a supported codec, with no other audio besides optional preview/crowd. Unknown audio names also prevent this fallback because they could be stems. Named own Drum stems remain preferred. The production recording matcher compares five independent waveform windows and permits only stable offsets within eight seconds; wrong/edited recordings and weak evidence are refused. A sole song file cannot prove Guitar/Bass/Vocals, supply absent Drum notes or authorize isolated Drum estimation. The analysis-only callback keeps this option off.

Accepted source notes, lane colors, authored difficulties, rolls and tempo remain source-derived. Only the verified constant recording offset is applied. Uploaded playback bytes and SHA-256 remain unchanged. Recording receipts distinguish referenceScope full-recording from instrument, retain the matching part/files/windows and survive save, backup and same-recording reuse. Title-only lookup continues obtaining the selected chart and its own package audio, with no cross-package mixing. Missing or incompatible authored charts retain explicitly estimated fallbacks.

Seven new tests exercise the production SNG/MIDI parser and recording matcher, positive/negative recording matches, offsets, other-instrument refusal, backing-only and unknown-stem refusal, own-stem preference, absent Drum notes, all authored difficulty levels, four-pad lanes, original upload bytes, backups/reuse and desktop/mobile title-only retrieval. Across the relevant suites 185 tests passed and three optional pre-existing reference-file checks were skipped. Runtime syntax, asset paths, unique HTML IDs, offline version and whitespace checks pass.

Live validation fetched Youngblood's Enter Sandman / Metallica package (9a5efa898899858f27ef39fd45225f01) from the catalog CDN. It contains notes.chart, art and a single 3,164,756-byte song.opus file. FFmpeg decoded the actual 333.676780-second stereo recording for the UI/audio adapter; the production matcher verified five windows at zero offset. The uploaded song retained all 2,083 authored Expert Drum notes, four pad colors plus kick and byte-identical original audio, without an analyzer job. Backup and fresh saved-song playback passed. The catalog response in this focused check selected this actual community row; chart/audio downloads and waveform matching were real. Physical browser QA was unavailable. Downloaded music and chart test material remain outside the published repository.

Game version 98 and offline cache v98-1 ship this change. To use it, choose Drums (or Whole song), provide title and artist, and either upload the matching recording or choose Find chart & audio without a file. Existing estimates can be refreshed through Find authored chart or reuploading the same audio with community lookup enabled.
