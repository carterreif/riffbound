# Local instrument isolation (v139)

Add a song now offers **Isolate instruments before estimating charts (experimental)**, enabled by default. Only missing, estimated parts are sent through separation. Existing authored charts, recording-matched imports and separately supplied verified Drum audio remain preferred. Uncheck for already isolated recordings or for the lighter original mixed-audio estimator.

The worker loads ONNX Runtime Web 1.23.2 from jsDelivr and a pinned six-source Demucs ONNX export from StemSplitio. Model: `htdemucs_6s_fp16weights.onnx`; repository revision `49df9b6989cf2150840ea65b0bef77a2e471b678`; size 136,428,532 bytes; SHA-256 `7ce55792e2231c93fbf92de95f5fd5b3a5e6c89f7db690dfd693e8f1dce56869`. Bytes are length/hash verified before use and before reuse of the separate browser model cache. Model weights are downloaded at runtime, not bundled into the game or its offline precache. Runtime access and uncached model download need internet. Audio never goes to a separation server.

The existing mono 22,050 Hz analysis signal is interpolated to the model's stereo 44,100 Hz input (duplicated mono). The fixed 343,980-sample model processes overlapping chunks; weighted overlap-add selects independent Drums=0, Bass=1, Vocals=3, Guitar=4 rows. Other and Piano are not charted as Guitar. Output is averaged to mono and returned on the original 22,050 Hz sample clock, with exactly the original analysis length. This loses stereo separation cues and is not equivalent to a multitrack recording. Sources can leak into each other; no exact-chart or automatic waveform-match claim is made.

Each part is then passed independently to the existing chart worker, with mixed-song mode off and no recording-specific reference hash. Analysis provenance is retained in that part's audio review. Separated PCM is temporary, not saved as the song's audio. Original uploaded bytes remain the playback and backup audio. Cancel terminates the model worker. Download, runtime, shape, nonfinite output and memory failures show an error; the operation does not silently claim isolation or substitute mixed audio. A user may explicitly uncheck isolation and retry. Working authored parts can still be retained if a missing part fails, using existing partial-success handling.

Browser CPU inference can take several minutes per song and substantial RAM. The first download is approximately 130 MiB plus runtime. Desktop Chrome or Edge is recommended; low-memory devices may fail. The feature is marked experimental.

Validation: real pinned ONNX native CPU inference produced finite `[1,6,2,343980]` output. ONNX Runtime Web 1.23.2 WASM inference in Node also completed a real chunk (about 21 seconds). Default all-graph optimization aborted with this model; shipped configuration disables graph optimization, prepacking, CPU memory arena and memory patterns, which completed successfully. The worker uses one thread, avoiding cross-origin isolation headers that would interfere with embedded video.

Focused checks: 74 tests, 73 passed, one optional external recording corpus skipped, zero failures. Includes odd chunk-stride timeline reconstruction, all four independent rows, malformed outputs, desktop/mobile upload/persistence, unchanged original audio bytes, per-part provenance, cancellation, opt-out, authored import and recording matching regressions. No physical browser/phone run or user band recording was available; native/WASM signal checks establish inference compatibility, not real-song transcription accuracy.

Sources: https://github.com/facebookresearch/demucs (Demucs); https://github.com/StemSplit/demucs-onnx/blob/main/docs/browser.md (browser export and row order); https://huggingface.co/StemSplitio/htdemucs-6s-onnx (model); https://github.com/microsoft/onnxruntime (runtime).
